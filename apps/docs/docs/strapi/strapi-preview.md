# Strapi Preview

Strapi preview lets editors check content before it is published. It is most useful for reviewing draft pages, localized updates, SEO fields, media, and page-builder changes in the same context where visitors will eventually see them.

The frontend exposes a secured preview route. Strapi admin integration is intentionally left as deployment configuration because the URL depends on the content type and the resolved site domain.

See the official [Strapi Preview documentation](https://docs.strapi.io/cms/features/preview) for the upstream feature overview.

:::tip Live Preview
Strapi Growth and Enterprise plans support **Live Preview**, which updates the preview as editors change content. See [Strapi Live Preview](https://docs.strapi.io/cms/features/preview#live-preview).
:::

## Preview Button

The editorial tool should open the UI preview route:

```http
GET /api/preview?secret=$STRAPI_PREVIEW_SECRET&url=/<path>&status=draft|published&locale=<locale>
```

Required variables:

```bash
STRAPI_PREVIEW_SECRET=
```

`STRAPI_PREVIEW_SECRET` must be configured in EmpresaX and in the system that creates preview links. The `url` must be same-origin with EmpresaX.

## Fetching Draft Content

Page and editorial-content fetching reads `draftMode().isEnabled`. When draft mode is active, requests send `status: "draft"` to Strapi and do not force `contentStatus: "published"`.

This keeps the same public page renderer while changing which Strapi document status is fetched.

## Troubleshooting

- Preview button missing in Strapi: configure the preview URL for the target content type and include the secret, resolved host, locale and slug.
- Preview opens but shows published content: check matching `STRAPI_PREVIEW_SECRET` values and browser cookie behavior.
- Preview opens the wrong locale: verify the document locale and URL generated by `apps/strapi/config/admin.ts`.
- Frontend preview route behavior is documented in [Preview API](../ui/built-in-api-routes/preview.md).
